## 2. Timeline: 특정 시점의 개인 기록과 상대 차이

`participantId`로 본인 프레임을 찾고, Match 상세의 반대 팀 + 같은 `teamPosition` 참가자 하나를 역할 상대 후보로 골랐다. 이는 Riot 추정 포지션 기준 비교이며 실제 이동 동선으로 식별한 상대가 아니다. 정글은 정글 상대 비교로 표시하며 라인전 승리로 해석하지 않는다.

각 7·10·14·15분에 가장 가까운 프레임을 사용하되 5초 이내인 경우만 채택하고 실제 `timestamp`를 기록했다. 해당 시점 전에 게임이 끝났거나 프레임/상대가 없으면 해당 비교는 제공하지 않는다. 보간하거나 경기 종료값을 소급하지 않는다.

- 골드 차이: 본인 `totalGold` − 상대 `totalGold`. `currentGold`는 보유 골드로 다른 지표다.
- 경험치 차이: 본인 `xp` − 상대 `xp`.
- 라인 CS 차이: 본인 `minionsKilled` − 상대 `minionsKilled`.
- 총 CS 차이: 양쪽의 `(minionsKilled + jungleMinionsKilled)` 차이.

## 4. 수집·저장 설계에 반영할 점

- 현재 계획은 조회 대상 한 명의 선택 필드를 저장하는 방식이다. 원본 10명 전체 저장 또는 데이터베이스 변경은 이번 작업에서 하지 않았다.
- Match 상세만으로 제공되는 지표와 Timeline이 필요한 10분/15분 지표를 구분한다. 특정 시점 비교에는 본인 값, 차이, 기준 시점, 실제 프레임 시각, 상대 선택 기준을 함께 남기는 것이 추적에 유리하다.
- 일부 수치는 소수 또는 음수다. 모든 통계를 비음수 정수로 검증하지 않는다.
- 미제공은 해당 지표 집계에서 제외한다. 0은 관측값으로 포함한다. 관측 횟수와 전체 경기 수를 별도로 제공한다.
- Timeline 제공 여부가 부족해도 Match 상세 기반 지표까지 실패시키지 않도록 후속 모델에서 유효성 범위를 나누는 것을 권장한다.
- 선수 표본은 실제 솔로 랭크에서 플레이한 포지션으로 분류한다. 선수의 프로 포지션으로 모든 경기를 단정하지 않는다.
- 대상 선수끼리 같은 경기에 참가할 수 있으므로 개인 경기 기록 수와 고유 HTTP 응답 수를 구분했다.
- field-observations.json의 통합 최소·최대는 타입/범위 검증용이다. 개인 성향의 통계는 summary.json에 선수별로 계산했다.

## 5. 경기 제외 기준의 검증 범위

- 이번 수집은 queue=420을 요구하고, 상세 응답에서 queueId·대상 PUUID를 재검사했다.
- `endOfGameResult`가 존재하면서 GameComplete가 아니면 임시 제외, 개인의 `gameEndedInEarlySurrender=true`도 임시 제외하고 다음 ID 페이지로 보충했다.
- 이는 조사용 운영 기준이다. early surrender가 모든 큐에서 다시하기와 정확히 동치인지는 이번 결과로 확정하지 않는다. 정상 완료·일반 항복은 포함했고 임의의 분 단위 길이 기준은 쓰지 않았다.
- 제외 사례·보충 페이지·원인 기록은 summary.json에 있다. 제외 사례가 없는 표본이라면 다시하기 판정은 검증되지 않은 것이다.
- 목록 탐색 상한은 계정별 200 ID다. 20개가 안 되거나 더 조회할 ID가 없으면 확보 표본 수를 기록한다.

7분 골드·XP 20% 조건은 Timeline 개인 표본 25건에서 API 값과 25건 일치했다. 14분은 25건 중 24건 일치하고 1건 불일치했다. 상세 수치와 한계는 [LANING_VALIDATION.md](LANING_VALIDATION.md), 전체 필드 제공 여부는 [FIELD_OBSERVATIONS.md](FIELD_OBSERVATIONS.md)에 정리했다.

## 파일과 재현

- `summary.json`: 선수별 표본 수, 실제 포지션, 필드 분포, 개인 물음표 핑 합계·평균·최소·최대.
- `player-matches.json`: 해당 선수의 선택 필드만 추출한 경기별 관측값. 없는 필드는 그대로 빠져 있다.
- `field-observations.json`: 경로별 존재 수·누락 수·타입·관측 범위.
- `timeline-snapshots.json`: 본인 스냅샷, 상대 차이, 실제 프레임 시각.
- `challenge-configs.json`: 현재 공식 도전과제 설명.
- `request-log.json`: 요청 결과 및 rate-limit 헤더. 키·토큰은 포함하지 않는다.
- `collect.py`, `analyze.py`: 조사 재현용 Python 표준 라이브러리 스크립트. 제품 코드가 아니다.

이미 환경변수에 LOL_API_KEY가 설정된 셸에서 `python3 collect.py` 후 `python3 analyze.py`를 실행한다. `RIOT_AUDIT_CACHE`로 임시 응답 캐시 경로를 지정할 수 있다. 자격증명은 파일에 넣지 않는다.
