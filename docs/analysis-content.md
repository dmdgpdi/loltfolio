# 플레이 성향 분석 콘텐츠

## 문서의 목적과 상태

사용자에게 보여줄 분석 콘텐츠를 다듬기 위한 기획 목록이다. 기존 대화의 메인 콘텐츠, 탱킹·생존·지원·CC 테마, 추가 카드 후보를 모았다. 기존 ‘전투 성향’ 카드는 서로 다른 행동별로 분리했다. 이름과 출시 범위, 대표 수치, 노출 순서는 검토 중이며 아래 목록 전체를 구현하기로 확정한 것은 아니다.

원천 필드는 현재 저장하는 `PlayerMatch`를 기준으로 한다. 현재 정의한 19개 분석 개념의 입력·결과 계약과 순수 계산·검증 테스트를 구현했다. 분석 입력 Reader·DTO Reader의 저장 경기 변환·조회·순수 계산 연결을 구현했다. 조회 GET API도 연결했으며 검색·최초 생성·최신화 Command 연결은 아직 없다. 분석 결과는 저장 경기에서 계산하고 스냅샷으로 저장하지 않는다. 이 문서의 추가 후보 전체나 보류 정책을 구현한 것은 아니다. 모든 출력 수치는 **가상 예시**다. 표의 예시는 각각 독립적이며 하나의 공통 경기 데이터에서 계산한 값이 아니다.

## 공통 표시와 계산 기준

### 의사소통 스타일 도메인

[CommunicationStyle](../src/backend/analysis/domain/CommunicationStyle.ts)은 경기별 핑 관측에서 의사소통 스타일을 계산하는 불변 값이다. `analyze(records)`는 Result로 결과 또는 `InvalidPingCountError`를 반환한다. 공통 표본을 중심으로 만들었던 `AnalysisSample`은 제거했다.

- 입력 `CommunicationRecord`는 분석이 소유하는 한 경기의 핑 관측 계약이다. `match`의 클래스·타입에 의존하지 않는다. 경기 선정·식별·중복 검증은 이 객체의 책임이 아니며, 실제 조회와 변환 경계는 이후 설계한다.
- 물음표·위험·후퇴·getBack·이동·총공격·도움 요청 7종의 합계·평균·최다와 유효·미제공·판별 불가 표본 수를 제공한다. 종류마다 표본 수의 합은 입력 경기 수와 같다.
- 실제 0은 계산에 포함한다. 유효 관측이 없으면 `UNAVAILABLE`로 표현하고 숫자를 만들지 않는다. 관측은 있으나 모두 0이면 `AVAILABLE`과 합계·평균·최다 0을 반환한다.
- 횟수는 0 이상의 안전한 정수여야 하고 합계도 정밀도가 보장되어야 한다. 잘못된 값을 미제공으로 숨기지 않는다. 계산값은 반올림하지 않는다.
- 입력을 보존하지 않고 결과를 동결한다. DB·HTTP·Repository·Application Service 연결은 아직 없다. 가장 많이 사용한 핑과 비중, 나머지 핑 지표는 후속 작업이다.

### 집계 원칙

- 기본 범위는 선택한 플레이어·큐의 최근 최대 20개 ID에서 확보한 분석 대상 경기다. 분석 제외 조건은 [경기 수집과 저장](match-data.md)을 따른다.
- 분석 대상의 포지션별 경기 수를 함께 제공한다. TOP·JUNGLE·MIDDLE·BOTTOM·UTILITY 각각의 경기 수와 포지션 없음(NONE)·미제공(NOT_PROVIDED)·판별 불가(UNKNOWN)의 경기 수를 구분한다. 플레이하지 않은 포지션은 0경기로 표현한다. 이 분포는 분석 대상 경기 수와 합계가 일치해야 한다.
- 포지션별 경기 수는 카드 적용 대상과 노출 여부를 판단하는 근거로 사용한다. 해당 포지션의 경기 수와 카드 개별 지표의 유효 표본 수는 별도로 제공한다. 계산은 유효 표본 1경기부터 허용하고, 카드 전체의 노출·숨김 기준은 후속 결정이다.
- 향후 포지션별 분석을 위해 경기별 포지션·큐·게임 규칙·맵과 통계의 제공 상태를 보존한다. 포지션이 없는 게임에 역할을 추정해 넣지 않는다. 현재 저장 구조를 유지하며, 장기 분석을 위한 수집 범위·보관 기간 확대는 별도 작업으로 결정한다.
- `20판`은 고정 문구가 아니다. 실제 경기 수와 지표별 유효 표본 수를 표시한다. 정글 카드라면 `최근 정글 8경기`, 일부 값이 없으면 `분석 18경기 중 해당 지표 15경기`처럼 범위를 밝힌다.
- 원천 필드에서 `ping.*`, `vision.*` 등의 경로는 `PlayerMatch.stats` 아래를 뜻한다. `win`, `position`, `champion` 등은 경기 기본 정보다. 실제 매핑은 [toPlayerMatchStats.ts](../src/backend/match/infrastructure/riot/toPlayerMatchStats.ts)를 확인한다.
- 합계·평균·최댓값·조건 충족 경기 수는 해당 값이 AVAILABLE인 표본으로 계산한다. 실제 0은 포함하고 NOT_PROVIDED·UNKNOWN을 0으로 대체하지 않는다. 합계에도 사용한 표본 수를 표시한다.
- 여러 필드가 필요한 계산은 동일한 경기 집합을 사용한다. 예를 들어 솔로킬 비중은 두 값이 모두 AVAILABLE인 경기의 `솔로킬 합 / 킬 합 × 100`이며 경기별 비중의 단순 평균과 다르다.
- 경기 수 비율은 `조건을 충족한 경기 수 / 조건을 판별할 수 있는 경기 수`다. 승률 계산에는 승패도 AVAILABLE이어야 한다.
- 두 불리언의 OR로 표현하는 첫 관여는 어느 하나가 true면 관여가 확정된다. 둘 다 false이면 미관여다. 나머지 경우는 판별 불가로 두며, 미관여에 넣지 않는다. 세부 항목과 합산 항목의 표본 수가 다를 수 있다.
- 유효 표본이 없거나 비율의 분모가 0이면 0으로 만들지 않는다. 계산은 유효 표본 1경기부터 허용하며, 표시 문구·카드 노출 기준·반올림 자릿수는 이후 정한다.
- 아래 대표 수치는 카드 구성 제안이다. 기본 구성은 대표 수치 1개 + 보조 수치 2~3개 + 설명 1개로 하고, 나머지 항목의 상세 노출 여부를 정한다.
- 타인·동일 티어 대비 순위나 성격을 단정하지 않는다. 승패별 기록 차이는 관찰 결과이며 승리 원인이라고 표현하지 않는다.

### 합의: 원천 관측·판별 불가·입력 오류

2026-11-07에 합의한 정책이다. 아래 원칙의 문서화가 완료되었으며, 모든 모델에 대한 구현 완료를 의미하지 않는다. 나머지 설계 항목을 먼저 논의한 뒤 계산·검증 코드를 구현한다.

| 구분 | 의미 | 처리 |
| --- | --- | --- |
| 실제 값 | 필요한 자료형과 의미에 맞는 0·false 등을 확보함 | AVAILABLE로 보존하고 해당 지표의 유효 표본에 포함 |
| 미제공 | 원천 필드가 없거나 null임 | NOT_PROVIDED로 보존. 0·false로 채우지 않음 |
| 판별 불가 | 분석에 필요한 분류나 비교·결론을 결정할 수 없음 | 해당 관측·판정은 UNKNOWN. 관계없는 다른 지표까지 판별 불가로 만들지 않음 |
| 집계 계산 불가 | 유효 표본이 없거나 비율의 분모가 0임 | 결과는 UNAVAILABLE로 구분하고 수치를 제공하지 않음 |
| 입력 오류 | 숫자 필드에 문자열이 오는 등 기대한 자료형을 위반함 | 입력 오류로 구분. 미제공·UNKNOWN·0으로 바꾸거나 조용히 건너뛰지 않음 |

**포지션 의존 여부는 분석별로 판단한다.** 전체 핑 평균이나 전체 시야 통계처럼 역할 구분이 필요 없는 분석은 해당 지표가 확보되어 있으면 역할 미확보 경기도 사용한다. 포지션이 없다는 이유만으로 전체 지표를 UNKNOWN으로 만들거나 경기를 통째로 제외하지 않는다. 반면 포지션별 세분화·정글 전용 집계·같은 역할 상대 비교에는 역할 정보가 필요하다. 역할을 확보하지 못하면 해당 분류·비교는 판별 불가로 남기고 특정 역할에 임의 배정하지 않는다. 원천 역할의 NOT_PROVIDED·UNKNOWN 상태는 그대로 보존하며, NONE은 포지션 구분이 없는 실제 값으로 구분한다.

본인 골드가 있어도 비교 상대를 특정할 수 없으면 **상대 골드 차이는 UNKNOWN**이다. 이때 확보된 본인 골드까지 버리거나 상대 골드를 0으로 가정하지 않는다.

**필요한 정보만으로 결론이 확정되면 계산한다.** 첫 포탑 관여는 다음과 같이 판단한다.

| 직접 파괴 | 어시스트 | 전체 관여 |
| --- | --- | --- |
| true | 미제공 또는 판별 불가 | 관여 확정 |
| false | 미제공 또는 판별 불가 | 판별 불가 |
| false | false | 미관여 확정 |

판별 가능한 경기만 해당 비율의 분모로 사용한다. 예를 들어 분석 20경기 중 관여 여부를 판별할 수 있는 15경기에서 6경기에 관여했다면 관여율은 6/15다. 나머지 5경기는 미관여로 세지 않고 판별 불가 표본으로 보존한다. 여기서 이유와 표본 수를 보존한다는 것은 원천 미제공·판별 불가·분모 0 등 현재 모델이 구분하는 상태와 유효·제외 표본 수를 유지한다는 뜻이며, 임의의 수치를 만들거나 모든 경기의 상세 오류 이력을 저장하라는 의미는 아니다.

**계산할 수 없는 지표는 제공하지 않는다.** 솔로킬과 전체 킬이 모두 0이면 두 원천 값은 정상 AVAILABLE(0)이지만 비중은 분모가 0이므로 제공하지 않고 넘어간다. 모든 경기에서 해당 지표가 미제공이면 그 집계도 제공하지 않는다. 내부 계약에서는 계산 불가 상태·사유와 표본 수를 유지하며 0%·평균 0으로 대체하지 않는다. 지표별 계산은 아래 합의에 따라 유효 표본 1경기부터 허용하며, 카드 전체의 화면 노출은 후속 결정이다.

입력 오류의 예는 `soloKills: "많음"`이다. 정상 숫자 `3`, 실제 값 `0`, 미제공 `null`과 다르다. Riot 응답 경계에서는 현재의 INVALID_RESPONSE 같은 오류로 구분한다. 도메인별 오류 타입·오류 코드와 한 입력 오류가 전체 작업에 미치는 범위는 이후 구현 계약에서 정한다.

### 보조 타입과 결과의 의미

- `AnalysisObservation<T>`는 새 모델들의 원천 관측 계약이다. AVAILABLE·NOT_PROVIDED·UNKNOWN을 구분하며 match의 타입을 가져오지 않는다.
- `AnalysisMetric<T>`는 지표별 유효·미제공·판별 불가 표본 수와 AVAILABLE 결과 또는 UNAVAILABLE 상태다. 실제 0은 AVAILABLE의 값이고, 계산할 수 없으면 `value`가 없다. 기존 구현 모델의 계약을 이번 작업에서 바꾸지는 않는다.
- `CountStatistics`는 동일 유효 표본의 합계·평균·최다·양수 관측 경기 수다. 0회 경기 수는 `sampleCount - occurredMatchCount`로 얻는다. 횟수 지표에만 사용하며 골드 차이·비율·시간에 동일 정수 규칙을 강제하지 않는다.
- `MatchFrequency`는 조건을 판별할 수 있는 표본의 충족 경기 수와 백분율이다. `AnalysisShare`는 두 값의 공통 표본 합계 비율이며, 표본 없음과 분모 0을 구분한다. 경기별 비율의 평균과 서로 대체하지 않는다.
- `PreferenceDistribution<T>`는 확보된 선택의 값별 경기 수 목록이다. 서로 다른 챔피언 수는 해당 목록 길이다. 최다 동률은 모두 반환하고 빈도 내림차순으로 나열한다. 동률 내부 순서는 고정하되 순위 의미를 부여하지 않는다. 고정 순서의 구체적인 키는 구현 시 정하며 우열 판단에 사용하지 않는다.
- 이 보조 타입은 콘텐츠의 의미를 대신하는 도메인 중심 모델이 아니다. 각 스타일이 자기 표본 범위·단위·조건·입력 검증과 계산 규칙을 소유한다.

### 영역별 입력과 표본 경계

- 정글 입력의 `enemyJungleMonsterKills`는 challenges 원값이고 `enemyJungleMinionsKilled`는 `totalEnemyJungleMinionsKilled`다. 원값 의미가 다른 두 지표를 합산·대체하지 않는다. 전자는 평균 지표로 남기고, 정글 역할 이외의 경기와 역할 미확보는 개별 통계의 미제공 수에 섞지 않는다. 지표별 표본 합은 `jungleMatchCount`다.
- 라인전 입력의 우위 지표는 원천 숫자 그대로 보존한다. `LaningPoint`에는 10·15분 목표와 실제 프레임 시각, 본인 수치와 상대 차이 및 각 값의 확보 상태를 담는다. `LaningGrowth`의 `experience`는 경험치다. 결과의 본인·상대 평균은 항목별 유효 표본에서 계산하며 최대 레벨 우위를 특정 시점의 격차로 바꾸지 않는다.
- 역전의 `deficitMatchCount`는 유효한 역할·15분 상대 골드 차이에서 음수로 확인된 경기 수다. `deficitWinRate.sampleCount`는 승패까지 확보된 열세 경기 수다. 골드 차이가 미확보이면 그 이유도 별도로 세므로 표본 합을 `deficitMatchCount`와 같다고 가정하지 않는다. 승리 경기 중 최대 열세는 크기인 양수, 평균 골드 차이는 음수로 표현한다. 이 둘은 열세 후 승리한 경기만 표본으로 사용한다. NONE·역할 미확보는 상대 비교에 넣지 않는다.
- 피해 부담 입력의 팀 비중은 원천 비율이고 결과 `averageTeamDamageTakenPercentage`는 경기별 비율 평균에 100을 곱한 백분율이다. 여러 경기 전체 팀 피해 합계를 분모로 쓰는 비율이 아니다.
- 생존 입력의 `longestLifeSeconds`와 CC 입력의 `crowdControlSeconds`는 초 단위다. 한 자릿수 HP·큰 피해·여러 CC 생존은 중복될 수 있으며 합산하지 않는다. 무데스 빈도는 사망 횟수 AVAILABLE 관측만 판정한다.
- 보호 입력의 `healingToAllies`, `damageShieldedOnAllies`, `allySaves`는 각각 `totalHealsOnTeammates`, `totalDamageShieldedOnTeammates`, `saveAllyFromDeath`다. CC의 `immobilizations`는 `enemyChampionImmobilizations`다.
- 선택 취향의 대상은 챔피언과 포지션이다. 스펠 입력·조합 결과는 분석 계약에서 제거했다. 원천 match의 스펠 ID는 유지한다.
- 승패 비교는 승리·패배·승패 미제공·판별 불가 경기 수의 합이 `matchCount`다. 각 지표 평균의 표본 합은 해당 승패 집단 수다. 위험·후퇴 핑은 분리하며, 평균 차이는 승리 평균에서 패배 평균을 뺀다. 한쪽 평균이 계산 불가면 차이도 계산 불가다. 양쪽 지표 표본을 합쳐 원래 승패 수와 같다고 가정하지 않는다.
- 포지션 분포는 관측된 역할만 사용한다. NONE은 역할이 없는 실제 값이다. 정글·서포터 경기 수와 카드별 유효 표본 수는 서로 다른 정보다.

### 합의: 역할 분류·임계값 보류와 계산 표본 기준

2026-11-07 합의. 챔피언의 일반적인 역할 분류와 해당 경기의 실제 플레이·아이템 구성은 같지 않으므로 **탱커·힐러 분류는 보류**한다. 탱킹 분석은 받은 피해·감소시킨 피해·팀 내 받은 피해 비중, 보호 분석은 아군 회복·보호막 흡수·구출 같은 실제 기록을 제공한다. 챔피언 이름이나 포지션만으로 탱커 경기·힐러 경기라고 단정하지 않는다.

**팀 피해 30% 이상, 이동 불가 10회 이상 같은 임의 임계값 분석도 보류**한다. 문서의 해당 예시는 후보 기록으로 남기되 현재 구현 대상으로 취급하지 않는다. 평균·합계·최다·발생 경기 수처럼 원래 합의한 집계는 계속 제공한다. 여기서 임계값 보류는 솔로킬 발생의 `> 0`, 무데스의 `=== 0`, 열세의 음수 판정처럼 지표 의미에 필요한 기존 조건까지 없앤다는 뜻은 아니다.

**지표별 유효 표본이 1경기라도 있으면 계산하고 표본 수를 반드시 함께 반환**한다. 1경기 수치를 평소 성향으로 확정하거나 추가 신뢰도 등급을 붙이지 않는다. 여러 값을 조합하는 지표는 입력 경기 수가 아니라 해당 결론을 계산할 수 있는 유효 표본 수로 판단한다. 분모 0처럼 별도의 계산 불가 사유가 있으면 표본이 있어도 비율을 만들지 않는다.

**계산 불가 지표는 수치를 제공하지 않는다.** 내부에는 계산 불가 상태·사유와 표본 수를 보존한다. 카드 전체의 화면 노출, 강조·정렬과 표시 형식은 이후 결정하며 이번 합의로 추가 최소 경기 수나 카드 숨김 규칙을 만들지 않는다.

### 합의: 라인전 우위 원천 값 해석

2026-11-07 합의. `earlyLaningPhaseGoldExpAdvantage`, `laningPhaseGoldExpAdvantage` 두 원천 지표에 다음 규칙을 적용한다.

| 원천 값 | 분석 해석 | 달성률의 유효 분모 |
| --- | --- | --- |
| 숫자 1 | 조건 달성 | 포함 |
| 숫자 0 | 조건 미달성 | 포함 |
| 누락·null | NOT_PROVIDED | 제외 |
| 그 외 유효한 숫자 | UNKNOWN, 판별 불가 | 제외 |
| 문자열 등 잘못된 자료형 | 입력 오류 | 정상 표본으로 처리하지 않음 |

숫자 0은 라인전 패배가 아니라 Riot 우위 조건 미달성이라는 뜻이다. 1·0을 정확히 구분하며, 0보다 크다는 이유만으로 달성 처리하거나 문자열 숫자를 자동 변환하지 않는다. NaN·무한대 등 유효하지 않은 숫자는 기존 입력 검증 정책에 따라 오류로 처리하며 미지의 정상 숫자와 혼동하지 않는다.

예를 들어 `1, 0, 1, 미제공`이면 유효 3경기 중 2경기 달성으로 계산한다. 미제공·판별 불가 표본 수를 보존하고, 유효 표본이 없으면 달성률을 제공하지 않는다. 적용 범위는 합의한 소환사의 협곡 솔로·자유 랭크의 탑·미드·원딜이다.

이 판정은 Riot 원천 값을 해석하는 규칙이다. 10·15분 Timeline 골드·경험치 격차나 Riot 내부 판정식을 재현한 값으로 대체하지 않는다.

| 제어 와드 미구매 경기 | 3/20판 | 구매 값이 0인 경기 수 |
| 20분 전 와드 제거 관여 | 평균 2.1회/판 | `vision.wardTakedownsBefore20M` 평균 |

구매와 설치는 구분한다. 20분 전 지표는 Riot 제공 원값을 사용하며, 20분 이후 기록을 따로 역산하지 않는다.

[VisionStyle](../src/backend/analysis/domain/VisionStyle.ts)은 분석 소유 입력인 `VisionRecord`에서 행동별 합계·평균·0회 경기 수와 유효·미제공·판별 불가 표본 수를 계산한다. 입력 매핑은 제어 와드 구매 → `controlWardsBought`, 와드 설치 → `wardsPlaced`, 제거 → `wardsRemoved`, 20분 전 제거 관여 → `wardTakedownsBefore20Minutes`다. 실제 match 조회·변환 연결은 아직 없다.

제어 와드 미구매 경기 수는 `activities.controlWardsBought.zeroMatchCount`이며, 미관측은 포함하지 않는다. 유효 관측이 없으면 `UNAVAILABLE`이고 미구매 수 0을 만들어 반환하지 않는다. 빈 입력도 허용하며, 실제 0은 AVAILABLE 집계에 포함한다. 각 행동의 유효·미제공·판별 불가 표본 수 합은 입력 경기 수와 같다. 횟수와 합계는 0 이상의 안전한 정수여야 하며, 계산값을 반올림하지 않고 결과는 불변 값으로 보존한다. 포지션·모드별 적용과 노출 기준은 아직 적용하지 않는다.


### 3. 정글 스타일

정글 포지션으로 플레이한 경기의 행동을 보여준다. **대표 후보: 평균 적 정글 몬스터 처치 지표.** `position`이 AVAILABLE이고 `JUNGLE`인 경기만 대상으로 한다.

전체 분석 대상 중 정글 경기 수를 먼저 확인한다. 예를 들어 ‘분석 20경기 중 정글 8경기’로 표시하고, 개별 지표가 6경기에서만 확보되었다면 그 유효 표본 수도 구분한다. 정글 0경기는 카드 비노출 판단의 근거가 되며, 계산은 지표별 유효 표본 1경기부터 허용하며 최종 카드 비노출 규칙은 이후 결정한다. 포지션 없음·미제공·판별 불가인 경기를 정글 표본에 포함하지 않는다.

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 평균 적 정글 몬스터 처치 지표 | 3.2/판 | `jungle.enemyJungleMonsterKills` 평균 |
| 평균 바위게 처치 | 2.1회/판 | `jungle.scuttleCrabKills` 평균 |
| 초반 라이너 처치 | 총 12킬 | `jungle.killsOnLanersEarlyJungleAsJungler` 합계 |
| 드래곤 처치 관여 | 평균 1.6회/판 | `objective.dragonTakedowns` 평균 |
| 바론 처치 관여 | 평균 0.7회/판 | `objective.baronTakedowns` 평균 |
| 버프 스틸 | 총 5회 | `jungle.buffsStolen` 합계 |

`enemyJungleMonsterKills`와 `totalEnemyJungleMinionsKilled`는 별개다. 두 값을 대체·합산하거나 캠프 수로 표시하지 않는다. 적 정글 지표의 최종 표시 단위는 원값 정의 확인 후 확정한다.

### 4. 최초의 남자 — 시작이 반이다

첫 킬과 첫 포탑에 얼마나 관여했는지 보여준다. **대표 후보: 퍼스트 블러드 전체 관여율.** 최종 카드 이름은 검토 대상이다.

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 퍼스트 블러드 직접 획득 | 5/20판 | `combat.firstBloodKill`이 true인 경기 수 |
| 퍼스트 블러드 어시스트 | 3/20판 | `combat.firstBloodAssist`가 true인 경기 수 |
| 퍼스트 블러드 전체 관여율 | 40% | 위 두 필드의 OR로 관여 경기 비율 |
| 첫 포탑 직접 파괴 | 4/20판 | `objective.firstTowerKill`이 true인 경기 수 |
| 첫 포탑 파괴 어시스트 | 2/20판 | `objective.firstTowerAssist`가 true인 경기 수 |
| 첫 포탑 전체 관여율 | 30% | 위 두 필드의 OR로 관여 경기 비율 |

직접 획득과 어시스트의 경기 수를 단순 합산하지 않고 경기별 OR로 중복을 방지한다. ‘시작이 반이다’의 관여 여부별 승률은 아래 추가 후보에서 다룬다.

[FirstBloodStyle](../src/backend/analysis/domain/FirstBloodStyle.ts)은 분석 소유 입력 `FirstBloodRecord`로 퍼스트 블러드 항목을 구현한다. 원천의 `firstBloodKill`은 `kill`, `firstBloodAssist`는 `assist` 관측으로 받는다. match 직접 의존이나 조회·변환 연결은 아직 없다.

- `kills`, `assists`는 각각 AVAILABLE인 표본에서 발생 경기 수(`occurredMatchCount`)와 반올림하지 않은 백분율을 제공한다. 미제공·판별 불가 표본 수를 각각 보존하고 실제 false는 유효 분모에 포함한다.
- `participation`은 어느 하나가 true이면 관여, 모두 false이면 미관여다. 나머지 조합은 `unresolvedMatchCount`로 보존한다. 판별 가능한 `sampleCount`를 분모로 `participatedMatchCount / sampleCount × 100`을 계산하며, 두 항목이 모두 true여도 한 경기로 센다.
- 항목별 유효 표본이 없으면 UNAVAILABLE이며 숫자를 만들지 않는다. 판별 가능하지만 모두 false이면 AVAILABLE의 0회·0%다. 빈 입력도 허용한다. 결과와 하위 집계는 불변 값이다.
- 직접 획득·어시스트·전체 관여는 분모가 다를 수 있으므로 각각의 표본 수를 함께 제공한다. 경기 선정·노출 기준·승패별 비교는 후속 작업이다.
- 입력은 이미 검증된 불리언 관측 계약이다. 미확보 상태도 정상 분석 입력이므로 이 계산은 예외나 실패 Result 대신 `FirstBloodStyle` 값을 직접 반환한다.

첫 포탑은 기존 `StructureStyle`이 `firstTowerKills`·`firstTowerAssists`·`firstTowerParticipation`으로 각각 발생 경기 수·유효 표본 수·백분율을 계산한다. 새 개별 집계는 `FirstTowerOccurrence` 계약을 사용하며 미제공·판별 불가 표본 수도 구분한다. 전체 관여는 기존 필드를 유지하고 `percentage`를 추가했다.


### 5. 라인전의 제왕

#### 합의한 적용 범위

2026-11-07 합의. 아래는 분석 정책이며 현재 수집·저장 코드의 적용 범위를 바꾸거나 데이터 삭제를 지시하는 규칙은 아니다.

- 소환사의 협곡 솔로 랭크·자유 랭크만 대상으로 한다. 다른 게임 규칙은 라인전 분석에서 제외한다.
- **라인전의 제왕은 TOP·MIDDLE·BOTTOM(탑·미드·원딜)에만 적용한다.** 정글·서포터를 라인전 승패의 표본에 포함하지 않는다. 전체 포지션 분포는 여전히 다섯 역할을 구분한다.
- **정글·서포터의 같은 역할 상대 격차는 계속 보존한다.** 정글은 오브젝트·갱킹·자원 확보 기록과, 서포터는 시야·아군 보호·CC 기록과 함께 각 역할 분석에서 활용한다. 골드·경험치 격차만으로 역할 수행의 승패나 실력을 판정하지 않는다.
- 포지션이 필요 없는 본인 수치는 전체 집계에서 역할 미확보 때문에 제외하지 않는다. 다만 이 카드에 사용하려면 탑·미드·원딜로 분류할 수 있어야 한다. 역할 미확보에 따른 카드 표본 제외와 원천 수치의 미제공을 혼동하지 않는다.
- 상대 격차는 반대 팀의 같은 역할 상대를 유일하게 특정할 수 있는 경기에서만 집계한다. 상대가 없거나 여러 명이면 해당 비교는 UNKNOWN이고 본인 기록은 유지한다. 실제 이동 동선을 추적한 상대가 아니라 경기 상세의 `teamPosition` 기준 상대다.
- Riot 우위 판정과 Timeline의 10·15분 실제 격차는 별도로 제공한다. 시점별 격차로 Riot 내부 판정을 재현하거나 서로 대체하지 않는다. 목표 시각에서 5초 이내의 가장 가까운 프레임과 실제 시각을 보존하는 기존 정책을 유지한다.

#### 표시할 지표

초반 성장과 상대 격차를 보여준다. **대표 후보: 평균 10분 상대 골드 차이.** 기존 ‘15분의 제왕’을 대체하는 콘텐츠다.

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 초반 골드·경험치 우위 조건 달성 | 8/20판 | `laning.earlyLaningPhaseGoldExpAdvantage`. 1은 달성·0은 미달성 |
| 라인전 골드·경험치 우위 조건 달성 | 11/20판 | `laning.laningPhaseGoldExpAdvantage`. 1은 달성·0은 미달성 |
| 평균 10분 라인 CS | 76개 | `laning.laneMinionsFirst10Minutes` 평균 |
| 평균 10분 상대 골드 차이 | +320골드 | 10분 Timeline 상대 골드 차이 평균 |
| 평균 15분 상대 CS 차이 | +12개 | 15분 Timeline 상대 라인 CS 차이 평균 |
| 경기 중 최대 상대 레벨 우위의 평균 | 1.2레벨 | `laning.maxLevelLeadLaneOpponent` 평균 |
| 평균 포탑 방패 획득 | 2.4칸/판 | `objective.turretPlatesTaken` 평균 |

Timeline의 본인 골드·경험치·레벨·라인 CS·정글 CS와 각 상대 차이로 상세 항목을 확장할 수 있다. `laneMinionsFirst10Minutes`와 Timeline 프레임의 라인 CS는 별도 출처로 취급하고 임의로 대체하지 않는다.

상대 차이는 본인에서 상대를 뺀 값이다. 같은 포지션 상대가 유일하게 확보된 표본만 사용한다. 포지션 NONE인 경기는 상대 비교를 하지 않는다. 10분·15분 전에 끝난 경기의 없는 표본을 0으로 넣지 않는다. 최대 레벨 우위는 15분 시점의 격차가 아니며, 우위 조건 지표는 정확한 골드 금액이 아니다. 포지션별 적용 범위는 위 합의를 따른다.

### 역전의 귀재

15분에 같은 포지션 상대보다 골드가 적었지만 최종적으로 승리한 기록을 보여준다. **대표 후보: 15분 골드 열세 경기 승률.** 라인전의 제왕과 함께 개인 라인전 우위·열세 이후의 결과를 살펴보는 카드다.

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 15분 골드 열세에서 승리한 경기 | 4/7판 | 15분 상대 골드 차이가 음수이고 `win`이 AVAILABLE인 경기 중 승리 경기 수 / 해당 열세 경기 수 |
| 15분 골드 열세 경기 승률 | 57.1% | 위 승리 경기 수 / 해당 열세 경기 수 × 100 |
| 승리한 경기 중 가장 컸던 15분 골드 열세 | 1,850골드 | 열세 후 승리한 경기의 15분 상대 골드 차이 최솟값을 열세 크기인 양수로 표시 |
| 열세 후 승리한 경기의 평균 15분 골드 차이 | −720골드 | 열세 후 승리한 경기의 15분 상대 골드 차이 평균. 음수 부호 유지 |

입력은 `laningSnapshots`에서 `minute === 15`인 표본의 `opponentDifference.value.gold`와 경기 기본 정보의 `win`이다. 상대 차이와 그 안의 골드 값이 모두 AVAILABLE이고, 승패도 AVAILABLE인 경기만 사용한다. 상대는 같은 포지션의 유일한 상대여야 하며, 포지션 NONE·미제공·판별 불가 또는 15분 표본이 없는 경기는 제외한다.

열세는 상대 골드 차이가 0보다 작은 경우다. 동률은 열세에 포함하지 않으며 별도의 최소 골드 차이 임계값은 두지 않는다. 작은 차이도 포함하므로 이를 큰 역전으로 표현하지 않는다. `4/7판`의 분모는 전체 분석 경기 수가 아니라 승패까지 확인된 15분 열세 경기 수다. 열세 경기가 없으면 승률은 계산 불가이며, 열세 후 승리가 없으면 최대·평균 열세도 계산 불가다. 이를 0골드로 표시하지 않는다.

설명 예시: ‘15분에 같은 포지션 상대보다 골드가 적었던 7경기 중 4경기에서 승리했습니다.’ 팀 전체 골드 열세, 경기 중 골드 차이의 회복, 본인의 역전 주도 여부를 뜻하지 않는다. 이 카드에서 확인하는 것은 개인의 15분 열세와 최종 팀 승리의 조합이다. 계산 최소 표본은 공통 합의의 유효 1경기를 따르고 카드 노출은 이후 결정한다.

### 6. 독고다이

혼자 기록한 처치의 규모와 빈도를 보여준다. **대표 후보: 전체 킬 중 솔로킬 비중.**

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 총 솔로킬 | 17킬 | `combat.soloKills` 합계 |
| 경기당 평균 솔로킬 | 0.85킬/판 | `combat.soloKills` 평균 |
| 전체 킬 중 솔로킬 비중 | 24% | 공통 표본의 `soloKills` 합 / `kills` 합 × 100 |
| 솔로킬을 기록한 경기 | 9/20판 | `combat.soloKills > 0`인 경기 수 |
| 한 경기 최다 솔로킬 | 4킬 | `combat.soloKills` 최댓값 |

설명 예시: ‘분석 가능한 20경기 중 9경기에서 솔로킬을 기록했으며, 전체 킬의 24%가 솔로킬이었습니다.’ 팀플레이를 하지 않는다고 단정하는 표현은 피한다.

[SoloKillStyle](../src/backend/analysis/domain/SoloKillStyle.ts)은 분석 소유 입력인 `SoloKillRecord`의 `soloKills`와 `kills`를 사용한다. match·DB 직접 의존과 경기 선정은 포함하지 않는다.

- `soloKills` 결과는 솔로킬 AVAILABLE 표본에서 합계·평균·최다·발생 경기 수(`occurredMatchCount`)와 유효·미제공·판별 불가 표본 수를 제공한다. 유효 관측이 없으면 UNAVAILABLE이며 실제 0은 AVAILABLE 통계에 포함한다.
- `share`는 두 관측이 모두 AVAILABLE인 공통 표본에서 `soloKillTotal / killTotal × 100`을 계산한다. 경기별 비중을 평균 내거나 서로 다른 표본의 합계를 나누지 않는다. 공통 `sampleCount`와 `excludedMatchCount`를 별도로 제공한다.
- `share`의 공통 표본이 없으면 UNAVAILABLE / `NO_VALID_SAMPLES`, 공통 표본은 있지만 전체 킬 합계가 0이면 UNAVAILABLE / `NO_KILLS`다. 전체 킬이 양수이고 솔로킬이 0이면 AVAILABLE의 0%다.
- 전체 솔로킬 통계와 비중의 표본 수·솔로킬 합계는 다를 수 있다. 위 설명처럼 같은 경기 범위의 수치로 함께 소개하려면 표본이 같은지 확인하거나 각각의 범위를 명시해야 한다.
- 관측 횟수와 계산하는 합계는 0 이상의 안전한 정수여야 한다. 두 값이 확보된 경기에서 솔로킬이 전체 킬보다 크면 오류로 반환한다. 값이 잘못되었을 때 누락이나 100%로 보정하지 않는다.
- 결과는 불변 값이며 평균·백분율을 반올림하지 않는다. Repository·Service 연결과 화면 노출 기준은 후속 작업이다.


### 7. 전투 관련 개별 카드

‘전투 성향’은 여러 카드를 묶는 분류로만 사용한다. 수적 열세 처치, 적·아군 포탑 근처 처치, 스킬 회피는 각각 독립 카드로 보여준다. 한 자릿수 HP 생존은 확장 테마의 ‘죽기엔 아직 이르다’에서 다룬다.

처치 상황은 중복될 수 있으므로 카드의 처치 수를 더해 전체 킬 수나 상호 배타적인 비중 그래프로 만들지 않는다. Riot 지표를 사용하며 직접 위치·체력 이력을 재구성하지 않는다.

### 8. 철거반장

포탑·방패·억제기 확보 행동을 보여준다. **대표 후보: 평균 포탑 파괴 관여.**

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 평균 포탑 파괴 관여 | 2.8회/판 | `objective.turretTakedowns` 평균 |
| 평균 포탑 방패 획득 | 2.1칸/판 | `objective.turretPlatesTaken` 평균 |
| 억제기 파괴 관여 | 총 11회 | `objective.inhibitorTakedowns` 합계 |
| 첫 포탑 파괴 관여 | 6/20판 | `firstTowerKill` OR `firstTowerAssist` |
| 포탑 파괴 관여 0회 경기 | 3/20판 | `objective.turretTakedowns === 0`인 경기 수 |

설명 예시: ‘경기당 평균 2.8회의 포탑 파괴에 관여했으며, 20경기 중 6경기에서 첫 포탑 파괴에 관여했습니다.’ 직접 마지막 타격과 관여를 구분한다. 방패가 적용되지 않는 게임 규칙의 처리와 카드 노출 범위는 확정해야 한다.

[StructureStyle](../src/backend/analysis/domain/StructureStyle.ts)은 분석 소유 입력인 `StructureRecord`에서 철거 성향을 계산한다. 포탑 파괴 관여 → `towerTakedowns`, 방패 획득 → `towerPlates`, 억제기 관여 → `inhibitorTakedowns`로 받아 행동별 합계·평균·0회 경기 수와 유효·미제공·판별 불가 표본 수를 제공한다. `activities.towerTakedowns.zeroMatchCount`가 포탑 관여 0회 경기 수다. 관측이 없는 행동은 `UNAVAILABLE`로 남기고 숫자를 만들지 않는다.

첫 포탑의 `firstTowerKill`, `firstTowerAssist`는 어느 하나가 true면 관여, 모두 false면 미관여다. 나머지 조합은 `unresolvedMatchCount`로 별도 보존하며 미관여나 유효 분모에 넣지 않는다. `firstTowerParticipation.sampleCount`는 판별 가능한 경기 수이고 `participatedMatchCount`는 그중 관여 경기 수다. 유효 표본이 없으면 `UNAVAILABLE`이며, 판별 가능하지만 전부 미관여라면 AVAILABLE의 0이다. 각 행동의 표본 합과 첫 관여의 판별 가능·불가 표본 합은 각각 입력 경기 수와 같다.

횟수·합계는 0 이상의 안전한 정수로 검증한다. 결과는 불변 값이며 반올림하지 않는다. 경기 선정, 모드별 적용, match 조회·변환, Repository·Service 연결은 아직 하지 않는다.


### 합의: 첫 포탑 집계 결과와 표시의 분리

2026-11-07 합의. 기존 철거 도메인에서 **직접 파괴·어시스트·전체 관여 각각의 발생 경기 수·유효 표본 수·비율**을 제공한다. 별도의 첫 포탑 도메인을 중복 생성하지 않고 ‘철거반장’과 ‘최초의 남자’에서 같은 계산 결과를 활용한다.

- 직접 파괴와 어시스트는 각각의 AVAILABLE 관측만 분모로 사용한다. 실제 false는 유효 표본이며 미제공·판별 불가는 미발생으로 세지 않는다.
- 전체 관여는 두 관측의 OR로 판정한다. 하나라도 true면 관여, 모두 false면 미관여, 나머지는 판별 불가다. 둘 다 true여도 관여 경기 수는 한 번만 센다.
- 세 항목의 유효 표본 수는 다를 수 있다. 한쪽 true로 전체 관여가 확정되면, 전체 관여의 유효 표본 수가 개별 항목보다 많을 수도 있다.
- 각 비율은 해당 발생 경기 수 / 해당 유효 표본 수 × 100이며 반올림하지 않는다. 유효 표본이 없으면 UNAVAILABLE로 남기고 수치를 만들지 않는다. 판별 불가 사유와 표본 수도 기존 공통 정책대로 보존한다.
- 화면은 경기 수·비율 중 필요한 항목을 선택하고 표시 자릿수를 결정한다. 화면에 당장 표시하지 않는다는 이유로 계산 계약에서 수치를 생략하지 않는다.

실제 도메인 결과의 필드명에 맞춘 가상 예시다. HTTP 응답 스키마나 화면 표시 형식을 확정한 것은 아니다. 구조물 활동 집계는 간략화를 위해 생략했다.

```ts
{
  matchCount: 20,
  firstTowerKills: {
    status: "AVAILABLE",
    occurredMatchCount: 4,
    sampleCount: 18,
    notProvidedCount: 2,
    unknownCount: 0,
    percentage: (4 / 18) * 100,
  },
  firstTowerAssists: {
    status: "AVAILABLE",
    occurredMatchCount: 3,
    sampleCount: 17,
    notProvidedCount: 3,
    unknownCount: 0,
    percentage: (3 / 17) * 100,
  },
  firstTowerParticipation: {
    status: "AVAILABLE",
    participatedMatchCount: 7,
    sampleCount: 19,
    unresolvedMatchCount: 1,
    percentage: (7 / 19) * 100,
  },
}
```

이 예시에서 전체 관여는 7/19판이다. 전체 입력 수 20을 비율의 분모로 사용하지 않는다. 직접 파괴·어시스트·전체 관여의 개별 집계와 비율 구현은 완료했다. 각 결과는 동결하며, 확보된 불리언에 문자열·숫자·null·undefined가 들어오면 InvalidFirstTowerObservationError를 반환한다. 다른 플래그가 true여도 잘못된 입력을 관여 확정으로 숨기지 않는다.

### 9. 챔피언 취향

자주 선택한 챔피언·포지션을 보여준다. 스펠 선택 취향은 제공 범위에서 제외한다. **대표 후보: 가장 많이 플레이한 챔피언.**

| 보여줄 데이터 | 출력 예시 | 저장 필드·계산 |
| --- | --- | --- |
| 가장 많이 플레이한 챔피언 | 아리, 12판 | `championId` 기준 빈도 집계 |
| 두 번째 챔피언 | 르블랑, 5판 | 같은 빈도 순위의 2위 |
| 서로 다른 챔피언 수 | 4종 | AVAILABLE `championId` 고유 개수 |
| 가장 많이 플레이한 포지션 | 미드, 17판 | AVAILABLE `position` 빈도 집계 |
| 포지션별 플레이 경기 수 | 탑 3·정글 8·미드 5·원딜 2·서포터 2판 | TOP·JUNGLE·MIDDLE·BOTTOM·UTILITY별 경기 수. NONE·NOT_PROVIDED·UNKNOWN은 별도 표시 |

챔피언 한글 표시명은 별도 매핑이 필요하다. 포지션 NONE은 포지션 없음으로 구분한다.

#### 합의: 빈도와 동률 처리

2026-11-07 합의. 챔피언·포지션의 빈도는 전부 보존하고, 목록은 경기 수 내림차순으로 정렬한다. 최다 항목은 동률을 모두 반환한다. 동률 항목의 나열 순서는 고정하지만 그 순서에 순위 의미를 부여하지 않는다. 예를 들어 아리 5판·르블랑 5판이면 둘 다 공동 최다이며, 나열 순서 때문에 1위·2위로 구분하지 않는다. 포지션도 미드 7판·정글 7판이면 공동 최다로 유지한다.

동률 내 고정 순서를 위한 구체적인 정렬 키는 구현 때 선택한다. 이는 결정적인 결과 순서를 위한 기술적 기준이지 별도의 성향·선호도 순위가 아니다. ‘두 번째 챔피언’은 이 목록의 단순 두 번째 항목을 단독 2위로 해석하지 않도록 해야 하며, 화면의 순위 표현은 아직 확정하지 않았다.

스펠 취향은 보류 후보가 아니라 현재 분석 제공 범위에서 제외한다. 따라서 스펠 조합의 동등성·동률 처리 논의는 필요하지 않다. `ChampionPreference.spellCombinations`와 `ChampionPreferenceRecord.summoner1Id`·`summoner2Id`는 타입에서 제거 완료했다. 경기 원천의 스펠 ID 수집·저장 중단이나 기존 데이터 삭제까지 합의한 것은 아니다. 분석 모델만 정리했으며 원천 match의 스펠 필드는 유지한다.

### 10. 승리와 패배의 두 얼굴

같은 사용자의 승패별 기록 차이를 보여준다. **대표 후보: 승패별 주요 지표 비교.**

| 보여줄 데이터 | 승리한 경기 예시 | 패배한 경기 예시 | 저장 필드 |
| --- | --- | --- | --- |
| 표본 수 | 12판 | 8판 | `win`으로 분류 |
| 물음표 핑 평균 | 4.2회 | 10.3회 | `ping.enemyMissingPings` |

| 팀 피해의 30% 이상을 받은 경기 | 9/20판 | 위 비율이 0.3 이상인 경기 수. 30% 기준은 보류 |

받은 피해와 감소시킨 피해를 더해 ‘총 탱킹량’으로 만들지 않는다. 팀 비중은 경기별 비율의 평균이며, 여러 경기의 팀 피해 총합 대비 비율이 아니다. 탱커 챔피언만 따로 집계하는 분류는 현재 보류한다.

## 실제 카드 표현 예시

### 철거반장

최근 20경기 · 포탑 파괴 관여 집계 20경기

**경기당 평균 포탑 파괴 관여 2.8회**

- 평균 포탑 방패 획득: 2.1칸 — 20경기 집계
- 억제기 파괴 관여: 총 11회 — 20경기 집계
- 첫 포탑 파괴 관여: 6/20판

‘포탑 파괴에 경기당 평균 2.8회 관여했으며, 20경기 중 6경기에서 첫 포탑 파괴에 관여했습니다.’

포탑 파괴 관여 0회 경기 수는 상세 항목 후보로 둔다. 대표·보조 항목의 최종 개수와 배치는 화면 설계에서 결정한다.

## 가다듬을 항목과 다음 작업

1. 메인 콘텐츠와 확장 테마 중 초기 노출 범위를 선택한다. 전투 관련 개별 카드도 각각 선택 대상으로 검토한다. 기존 우선 제안은 의사소통·시야·정글·최초 관여·라인전·독고다이·철거·승패 비교 8종이며 확정 목록은 아니다.
2. 카드 이름과 중복을 정리한다. 철거반장/포탑 철거 전문가, 생존 이름 후보들, 회복·보호 카드 이름을 통일한다.
3. 카드마다 대표 지표, 보조 지표, 상세 항목, 설명 문장을 선택한다. 값이 부족할 때 카드를 숨길지 일부만 보여줄지도 정한다.
4. 구현한 포지션별 경기 수를 기준으로 게임 규칙·맵·포지션별 카드 노출 범위를 정한다. 지표 계산은 유효 표본 1경기부터 허용한다. 탱커·힐러 등 챔피언 역할 분류에 따른 추천은 보류한다.
5. 핑 비교 범위와 적 정글 지표 단위·반올림 규칙을 확정한다. 임의 임계값 분석은 보류한다. 동률과 0분모는 위에서 합의한 정책을 따른다. 제공된 수치에서 임의 점수나 등급을 만들지 않는다.
6. 구현한 저장 경기→분석 입력→DTO GET 조회와 별도 최초 생성·최신화 Command를 검색 유스케이스에 연결한다.

최신 구현 범위와 전체 개발 순서는 [현재 진행 상황과 다음 작업](project-status.md)을 참고한다. 새로운 콘텐츠를 확정하거나 구현하면 이 문서의 항목·상태와 해당 문서를 함께 갱신한다.

## 구현 계약의 핵심

19개 분석 개념의 계산·검증·결과 동결과 저장 경기 매핑·DTO 조회를 구현했다. 입력·결과 필드는 [도메인 값모델](#도메인-값모델)의 타입을 기준으로 하고, 완료 이력은 누적하지 않는다.

- 포지션 분포는 여섯 실제 값과 미제공·판별 불가의 합이 전체 경기 수다. 최다 역할 후보는 NONE을 제외한 다섯 역할이다.
- 정글은 JUNGLE 경기만 집계한다. 몬스터 원지표는 유한한 비음수 소수의 평균, 나머지 횟수는 비음수 안전 정수로 처리한다.
- 라인전은 전체 matchCount와 적용 대상 laningMatchCount를 구분한다. 시점 누락은 NOT_PROVIDED, 부모 관측의 상태는 각 성장 항목에 전파한다. 스냅샷·격차·포탑 방패는 안전 정수이며 격차 음수를 유지한다. 중복·잘못된 목표 시점·실제 시각 ±5초 초과는 입력 오류다.
- 역전은 확보된 다섯 역할을 사용하며 별도 게임 규칙 필터는 없다. 비열세·패배로 승리 열세의 비충족이 확정되면 제외한다. 나머지 조합은 UNKNOWN 우선, 다음 NOT_PROVIDED로 한 번만 센다. 음수 골드가 확인되면 승패 누락도 deficitMatchCount에 포함한다. 승률은 골드 미확보 이유, 또는 열세가 확인된 경우 승패 미확보 이유를 보존한다.
- 챔피언·포지션 관측은 독립 집계한다. 빈도는 횟수 내림차순, 동률은 챔피언 ID 오름차순·역할 TOP/JUNGLE/MIDDLE/BOTTOM/UTILITY 순서다. 공동 최다는 모두 반환하며 표본이 없으면 빈 목록이다. 챔피언 ID는 양의 안전 정수로 검증하고 존재 여부·표시명은 조회하지 않는다.
- 상황별 처치·생존·회피·CC 횟수는 합계·평균·최다·양수 기록 경기 수다. 상황끼리 합산하지 않는다. 적 포탑 처치 비중은 공통 표본 합계로 계산하며 전체 킬 초과는 오류다. 표본 없음과 분모 0을 구분한다.
- 피해·회복·시간과 합계는 유한한 비음수이며 소수를 허용한다. 팀 피해 원비율은 0~1을 검증해 경기별 평균 × 100으로 반환한다. 무데스는 사망 AVAILABLE 표본의 실제 0만 센다.
- 승패 비교는 집단별·지표별 평균과 승리 평균−패배 평균을 반환한다. 한 집단이 없으면 확보된 평균은 유지하고 차이만 UNAVAILABLE이다. 미확보 승패는 집단에 넣지 않는다.
- 횟수 합계도 안전 정수 범위를 검증한다. 잘못된 확보 값은 집계 제외 뒤로 숨기지 않고 오류로 반환한다. 입력을 보관하지 않으며 결과와 중첩 지표를 동결한다.

조회·변환·HTTP 경계는 [분석 입력과 Query 조회 계약](analysis-read-contracts.md), 남은 작업과 검증 제한은 [진행 상황](project-status.md)을 따른다.
